# Linux / Windows parity matrix

Status, November 7, 2026 (PR-C, `windows-parity`). Linux behaviour is what the
current Linux build does. Every Windows entry is **unverified on hardware**: no
Windows build has run on a real machine, and Windows CI has not run either (hosted
runners billing-locked, Edison not registered yet). "Verified in source" means a
reviewer read the code path; it is not a test result. Evidence for each check is
recorded in [test-ledger.md](test-ledger.md); the visual checklist is in
[README.md](README.md).

## Known bugs (not requirements)

These were found while building the matrix. They are tracked separately from
parity: fixing one does not by itself establish parity.

| Id | Bug | Status |
| --- | --- | --- |
| B1 | Linux packages shipped cuDNN 9 and two NVRTC copies (≈1.55 GB unpacked) that inference never loads. CTranslate2 4.6.3's Linux wheel has no cuDNN or NVRTC references and runs the Whisper encoder's two Conv1D layers via im2col + cuBLAS GEMM. This is version-specific. | Fixed in PR-A: cuBLAS only; `scripts/check-engine-imports.py` fails the build if a future CTranslate2 references cuDNN/NVRTC. Verified on an RTX 4060 with `distil-small.en`, `large-v3-turbo` (full precision × VAD matrix) and `large-v3`. Windows wheel inspected statically (PR-C): `ctranslate2.dll` has no cuDNN reference; the bundled `cudnn64_9.dll` shim is pruned and the gate parses PE import tables. |
| B2 | `murmur` binary shipped unstripped (≈10 MB of symbols). | Fixed in PR-A (`[profile.release] strip = true`). |
| B3 | The same shared library copied 2–3 times instead of symlinked (≈20 MB unpacked). | Fixed in PR-A (`dedupe_libraries`). |
| B4 | Speech models download the latest Hugging Face revision with no pinned revision and no hash check, and an install cannot be cancelled; the `.complete` marker is the only integrity signal (`engine/murmur_engine/models.py`). `hf_hub_download` does resume. `large-v3-turbo` comes from a third-party repository (`dropbox-dash`), which a provenance field must record. | Fixed in PR-B: the engine no longer downloads; the app installs models from a signed manifest pinned to a commit with per-file SHA-256, resumable (re-hash from byte 0), pausable and cancellable; `large-v3-turbo`'s provenance note names the third party. |
| B5 | The engine was duplicated in the tar.gz; PyAV/FFmpeg (≈128 MB) and hf_xet (11 MB) were frozen but unused. | Fixed in PR-A. |
| B6 | The onefile engine unpacked hundreds of MB into `TMPDIR` on every start. | Fixed in PR-A (onedir). |
| B7 | Windows: `focusable:false` already gives the overlay WS_EX_NOACTIVATE through tao, but clicking Accept/Discard can still give keyboard focus to the WebView2 child HWND and take it from the target app. Fix: answer WM_MOUSEACTIVATE with MA_NOACTIVATE on the child, or handle pointer input only. | Closed in code (PR-C): protection = WS_EX_NOACTIVATE (pre-existing), the `WM_ACTIVATE` hand-back in `overlay/noactivate.rs`, and mousedown prevention on overlay buttons. The MA_NOACTIVATE subclass is kept but covers only the top-level window: WebView2's child windows belong to msedgewebview2.exe and Chromium answers WM_MOUSEACTIVATE itself; the subclassed count is logged at info. Verified in source, not run on hardware; checklist O3/O4/O7. |
| B8 | Windows: global-hotkey reports Released by polling GetAsyncKeyState, but modifiers may still be held when typing or pasting starts. Linux waits for them (`inject.rs`). Fix: wait on VK_CONTROL/VK_MENU/VK_SHIFT/VK_LWIN with GetAsyncKeyState. Verified in source, untested on hardware. | Closed in code (PR-C): shared bounded wait with a GetAsyncKeyState probe (Ctrl/Alt/Shift/LWin/RWin) before typing and pasting. Verified in source, not run on hardware; checklist H1–H3. |
| B9 | Windows: enigo returns an error when SendInput inserts fewer events than requested and `inject.rs` propagates it, but UIPI drops into elevated windows are still not reliably reported. Fix: compare the target's token integrity level (OpenProcessToken + TokenIntegrityLevel) with Murmur's before delivery and hold instead. | Closed in code (PR-C): target vs own token integrity level; unreadable → hold; secure desktop (OpenInputDesktop / name ≠ Default) → hold, in every mode. Verified in source, not run on hardware; checklist F9/F10. |
| B10 | Windows: target identity is the HWND only (`platform.rs` `native_focus`); HWNDs can be reused. Fix: HWND + PID + process start time. | Closed in code (PR-C): `Focus::Window` carries HWND + PID + process creation time; all compared. Verified in source, not run on hardware; checklist F3. |
| B11 | Windows CI: no CUDA and no GPU path; it publishes with a third-party action that bypasses the draft-release flow. | Closed in CI design (PR-C): Windows engine + cuBLAS components, Edison GPU job with module-origin evidence, assets attached to the draft with gh (softprops removed). Not run: runner not registered. |
